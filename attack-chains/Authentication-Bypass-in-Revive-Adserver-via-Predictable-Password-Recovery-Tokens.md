## Prerequisites & Requirements

### Required Tools

- [[tools/Burp-Intruder]]

### Target Environment

- Web application running Revive Adserver on PHP with nginx
- Accessible password recovery endpoint at /admin/password-recovery.php
- No rate limiting on recovery requests

### Initial Access Requirements

- Network access to the target web server
- Ability to inspect HTTP responses
- Local PHP environment for token generation

## Detailed Attack Procedures

### Step 1: Source Code Review
procedure: [[procedures/Review-Revive-Adserver-Source-Code-for-Token-Weakness]]

**Objective**: Identify the insecure token generation mechanism in the password recovery code.

**Instructions**: Download and analyze the Revive Adserver source code, focusing on /lib/OA/Dal/PasswordRecovery.php.

**Expected Output**: Confirmation of uniqid('', true) usage in generateRecoveryId function.

**Success Indicators**:
- Token generation relies on timestamp and microseconds
- Low entropy identified

### Step 2: Identify Weakness
procedure: [[procedures/Identify-Uniqid-Entropy-Weakness]]

**Objective**: Understand the predictability of tokens generated by uniqid().

**Instructions**: Review PHP documentation for uniqid() and note its reliance on system time without cryptographic security.

**Expected Output**: Awareness of less than 2^20 possibilities per second.

**Success Indicators**:
- Documentation confirms non-cryptographic nature
- Predictability based on time confirmed

### Step 3: Determine Server Timezone
procedure: [[procedures/Determine-Server-Timezone-from-HTTP-Headers]]

**Objective**: Infer the server's timezone to synchronize token prediction.

**Instructions**: Send a request to any endpoint and inspect the Date header in the response.

**Expected Output**: Date header like 'Date: Thu, 09 May 2019 21:26:20 GMT' indicating GMT+0.

**Success Indicators**:
- Timezone inferred as GMT
- Server time synchronized for prediction

### Step 4: Synchronize Local Timezone
procedure: [[procedures/Synchronize-Local-Timezone-to-Server]]

**Objective**: Align local system time with the server for accurate token generation.

**Instructions**: Adjust the attacker's system timezone to match the inferred server timezone (e.g., GMT).

**Expected Output**: Local time matches server time within microseconds.

**Success Indicators**:
- System timezone set to GMT
- Local uniqid() outputs align with potential server outputs

### Step 5: Enumerate Admin Emails
procedure: [[procedures/Enumerate-Admin-Emails-via-Password-Recovery]]

**Objective**: Identify valid admin email addresses for targeted recovery requests.

**Instructions**: Send POST requests to /admin/password-recovery.php with guessed emails and check responses for 'Email Password Reset sent'.

**Expected Output**: Confirmation of valid emails via success message.

**Success Indicators**:
- Valid admin emails discovered
- Recovery process triggered for targets

### Step 6: Generate Candidate Tokens
procedure: [[procedures/Generate-Candidate-Recovery-Tokens-Locally]]

**Objective**: Produce a list of possible recovery tokens using the same insecure method.

**Instructions**: Run the PHP script to generate 10,000 tokens:

Execute [[commands/generate-recovery-tokens-php]]:

```php
for($i=0;$i<=10000;$i++){ $recoveryId=strtoupper(md5(uniqid('',true))); $recoveryId=substr(chunk_split($recoveryId,8,'-'),-23,22); print $recoveryId."</br>\"; }
```

**Expected Output**: 10,000 formatted 22-character recovery IDs, e.g., '58FC30C5-3DB6-3XXX-XXXX'.

**Success Indicators**:
- Token list generated
- Tokens match the server's formatting

### Step 7: Brute-Force Tokens
procedure: [[procedures/Brute-Force-Recovery-Tokens-with-Burp-Intruder]]

**Objective**: Test generated tokens against the recovery endpoint to bypass authentication.

**Instructions**: Use Burp Intruder to send requests with each token to the password reset endpoint and monitor for success.

**Expected Output**: Successful reset link or admin login access.

**Success Indicators**:
- Valid token accepted
- Admin password reset achieved
- Unauthorized access gained
