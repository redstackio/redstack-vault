# Access-FrontPage-Configuration-File

## Summary

This procedure demonstrates how to exploit the public accessibility of the _vti_inf.html file on a Microsoft SharePoint server using FrontPage extensions, disclosing configuration details such as version numbers and internal scripting paths without authentication. It is primarily used in reconnaissance phases to gather information about the target's web application stack for potential further exploitation.

## Description

The _vti_inf.html file is a hidden configuration file generated by Microsoft FrontPage for SharePoint environments, containing metadata like the FrontPage version and URLs for server-side scripts. In vulnerable setups, such as the reported U.S. Department of Defense subdomain, this file is exposed publicly due to misconfigured access controls. Attackers can simply navigate to the URL in a web browser to view the contents, which include sensitive paths like _vti_bin/shtml.dll/_vti_rpc. This information can reveal the exact software version (e.g., 16.00.0.000) and enable targeted attacks, such as identifying exploitable endpoints. The procedure requires no special tools beyond a standard browser and assumes the target URL is known or discovered via subdomain enumeration.

## Requirements

1. Internet access to the target subdomain (e.g., https://███████)
2. A web browser like Firefox for direct navigation
3. No authentication credentials, as the file is publicly accessible

## Defense

Defensive measures and detection strategies:

- Implement access controls on _vti_* directories using IIS permissions or web application firewalls to restrict unauthenticated access
- Regularly scan for exposed configuration files using tools like Nuclei or custom scripts targeting FrontPage paths
- Monitor web server logs for anomalous GET requests to _vti_inf.html and block repeated accesses from suspicious IPs

## Objectives

1. Retrieve FrontPage version and scripting configuration from the target server
2. Identify internal SharePoint endpoints for reconnaissance
3. Enable planning of subsequent attacks based on disclosed software details

## Instructions

### Step 1: Launch Browser and Navigate to Target URL

**Context**: Open a web browser to directly access the exposed configuration file, simulating a simple reconnaissance probe.

No command required; use the browser's address bar:

```plaintext
https://███████/_vti_inf.html
```

> Enter the URL in Firefox. The page will render as plain HTML with embedded comments. Right-click and select "View Page Source" to inspect the configuration details, such as FrontPage version 16.00.0.000 and scripting URLs (e.g., FPShtmlScriptUrl="_vti_bin/shtml.dll/_vti_rpc", FPAuthorScriptUrl="_vti_bin/_vti_aut/author.dll").

### Step 2: Extract and Analyze Disclosed Information

**Context**: Review the HTML source to document the revealed data for use in further reconnaissance.

No command required; manual inspection:

```plaintext
<!-- FrontPage Configuration -->
<!-- FPShtmlScriptUrl="_vti_bin/shtml.dll/_vti_rpc" -->
<!-- Version: 16.00.0.000 -->
```

> Copy the relevant comments into a notes file. Look for patterns like _vti_bin paths, which indicate SharePoint internals. This step confirms the disclosure and prepares data for vulnerability research against the identified version.
