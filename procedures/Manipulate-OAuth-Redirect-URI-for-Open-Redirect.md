# Manipulate-OAuth-Redirect-URI-for-Open-Redirect

## Summary

This procedure exploits an open redirect vulnerability in the OAuth authorization flow of Lichess by modifying the redirect_uri parameter to an arbitrary external domain, allowing redirection to malicious sites after user authentication and facilitating phishing attacks.

## Description

The vulnerability arises from insufficient validation of the redirect_uri in the OAuth URL generated by a third-party site (lichess4545.com) integrating with Lichess. Without an allowlist or domain restrictions, attackers can alter the parameter to point to any domain. Upon authorization, users are redirected to the attacker-controlled site, where phishing pages can mimic legitimate applications to steal credentials or tokens. This targets web-based OAuth flows and requires browser access to manipulate URLs.

## Requirements

1. Web browser with developer tools enabled
2. Test account on the third-party site (e.g., lichess4545.com)
3. Valid Lichess account for authorization
4. Internet access to the target sites

## Defense

Defensive measures and detection strategies:

- Implement strict allowlists for redirect_uris in OAuth flows, validating against registered domains only
- Use state parameters and PKCE in OAuth to prevent tampering
- Monitor authorization logs for anomalous redirect_uris
- Educate users on verifying URLs during OAuth processes

## Objectives

1. Redirect authenticated users to a malicious external domain
2. Enable phishing by impersonating trusted applications
3. Demonstrate OAuth misconfiguration for validation

## Instructions

### Step 1: Access and Login to Third-Party Site

**Context**: Initiate the OAuth flow by logging into the vulnerable third-party site to trigger redirection to Lichess.

No command required; use browser to navigate to https://www.lichess4545.com/blitzbattle/ and enter test account credentials.

> Expected output: Login success and automatic redirect to Lichess OAuth URL.

### Step 2: Inspect and Modify OAuth URL

**Context**: Locate the redirect_uri parameter in the authorization URL and change it to a malicious domain.

No command required; open browser developer tools (F12), go to the Network or Console tab, and edit the URL parameter from https://www.lichess4545.com/auth/lichess/ to https://example.com/auth/lichess/. Submit the modified URL.

> Expected output: Authorization page updates with the new redirect_uri visible in the address bar.

### Step 3: Authorize the Request

**Context**: Complete the OAuth authorization to trigger the open redirect.

No command required; click the "Authorize" button on the Lichess page.

> Expected output: Post-authorization redirect to the specified malicious domain (e.g., https://example.com/).

### Step 4: Validate Exploitation

**Context**: Confirm the redirect and assess phishing potential.

No command required; inspect the final landing page to ensure it loads the arbitrary domain without errors.

> Expected output: Successful load of malicious site, simulating a phishing page.
