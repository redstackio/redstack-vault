# Inspect-Website-Source-Code-for-Plugins

## Summary

This procedure involves examining the HTML source code of a WordPress website to identify installed plugins and their versions, enabling the discovery of potential vulnerabilities through passive reconnaissance.

## Description

In a typical attack scenario, attackers inspect public-facing WordPress sites for plugin footprints in the HTML source, such as comments generated by plugins like Yoast SEO. This reveals versions that can be cross-checked for known issues. The target environment is any accessible web application using WordPress. Expected outcomes include extracting plugin details without direct interaction, minimizing detection risk. Prerequisites include basic web access and a browser or command-line tool like curl.

## Requirements

1. Public access to the target website (HTTP/HTTPS)
2. Web browser with developer tools or curl installed
3. No authentication needed for public pages

## Defense

Defensive measures and detection strategies:

- Remove or obfuscate plugin version comments in WordPress themes and plugins
- Use security plugins like Wordfence to monitor source code exposure
- Implement Content Security Policy (CSP) to limit script injection risks from discovered vulns

## Objectives

1. Extract plugin names and versions from HTML source
2. Identify outdated or vulnerable components
3. Prepare for further vulnerability validation

## Instructions

### Step 1: Fetch and View HTML Source

**Context**: Retrieve the raw HTML of the target page to search for plugin indicators without relying on browser rendering.

**Command** ([[commands/curl-fetch-html]]):
```bash
curl -s http://people.uber.com/ > source.html
cat source.html | grep -i 'yoast\|wpseo'
```

> This command silently fetches the page content and saves it to a file, then greps for Yoast-related strings. Expected output includes lines like "<!-- This site is using the Yoast WordPress SEO plugin v2.1.1 -->", revealing the plugin and version.

### Step 2: Analyze for Plugin Footprints

**Context**: Manually or programmatically scan the source for common WordPress plugin signatures.

**Command** ([[commands/curl-fetch-html]]):
```bash
curl -s http://people.uber.com/ | grep -E 'generator|wp-content/plugins'
```

> This extracts meta generator tags or plugin directory paths. Successful execution shows plugin directories or version info, confirming presence of components like Yoast.
