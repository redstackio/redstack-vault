# Retrieve-and-Download-Test-Log

## Summary

This procedure retrieves the results of the SSRF test from the application's 'Past Results' section and downloads the log file containing the exfiltrated HTTP responses.

## Description

After triggering the test, the app records the full interaction in a downloadable log, including requests to the malicious URL and server responses. Configuring the download to include HTTP details and plain text format ensures the metadata response is captured. This step completes the exfiltration in web apps with verbose logging, allowing attackers to obtain sensitive data without direct server access.

## Requirements

1. SSRF test completed with entry in 'Past Results'
2. Access to product page post-redirect
3. Text editor for log inspection

## Defense

Defensive measures and detection strategies:

- Sanitize logs to exclude sensitive responses (e.g., strip internal IPs)
- Restrict log downloads to admins or require approval
- Monitor for downloads of test logs with internal request traces

## Objectives

1. Access recorded SSRF interactions
2. Download raw HTTP logs for analysis
3. Exfiltrate metadata without alerting

## Instructions

### Step 1: Check Past Results

**Context**: Locate the test entry generated by the SSRF trigger.

Navigate to the product page, scroll to 'Past Results'; a new entry from the test should appear.

**Expected Output**: List of test records including the recent one.

### Step 2: Download Configured Log

**Context**: Export the log with full HTTP details.

Click 'Manage Test record' > 'Download log', check 'Include HTTP' checkbox, select 'Plain text' from Log Format dropdown, and download the 'log' file.

**Expected Output**: File saved locally with request/response data.
