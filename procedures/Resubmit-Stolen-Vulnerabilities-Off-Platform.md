# Resubmit Stolen Vulnerabilities Off-Platform

## Summary

This procedure involves directly contacting customers with stolen vulnerability details under a sockpuppet identity to claim duplicate bounties.

## Description

Using intimidating communications, the attacker resubmits data off-platform, pressuring customers for payments on supposed new disclosures.

## Requirements

1. Stolen vulnerability details
2. Contact information for customers
3. Sockpuppet identity for communications

## Defense

Defensive measures and detection strategies:

- Verify all submissions through official channels
- Report suspicious duplicate disclosures

## Objectives

1. Monetize stolen data
2. Pressure for bounty payments
3. Maintain anonymity

## Instructions

### Step 1: Compile Stolen Data

**Context**: Organize extracted report details for resubmission.

> Prepare intimidating messages about vulnerabilities.

### Step 2: Contact Customers Directly

**Context**: Send communications using sockpuppet handle to claim bounties.

> Use off-platform methods to submit duplicates.
