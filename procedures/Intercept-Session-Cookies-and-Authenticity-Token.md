# Intercept-Session-Cookies-and-Authenticity-Token

## Summary

This procedure captures session cookies and the Rails authenticity token from a non-privileged user's profile update request in Stocky, enabling reuse in unauthorized API calls.

## Description

After logging in as a non-privileged user, navigate to the profile page (/users/me) and trigger a form submission (e.g., update a field). Use browser developer tools or a proxy to inspect the network request, extracting the Cookie header (containing _stocky_session) and the authenticity_token from the form data or hidden input. This token, generated by Rails, is meant to prevent CSRF but is leaked here without proper auth checks.

## Requirements

1. Active non-privileged session in Stocky
2. Browser with dev tools or interception proxy
3. Access to https://stocky.shopifyapps.com/users/me

## Defense

Defensive measures and detection strategies:

- Implement strict CSRF token validation on all endpoints
- Monitor for unusual request patterns from low-privilege sessions
- Use short-lived session tokens and rotate on profile access

## Objectives

1. Obtain valid session artifacts for endpoint exploitation
2. Demonstrate token leakage vulnerability
3. Enable subsequent unauthorized admin creation

## Instructions

### Step 1: Login and Navigate to Profile

**Context**: Establish the session to be intercepted.

Login to https://stocky.shopifyapps.com with non-privileged credentials, then visit https://stocky.shopifyapps.com/users/me.

### Step 2: Trigger and Intercept Form Submission

**Context**: Update a profile field to generate an interceptable request.

Edit a field like first name and submit the form. In dev tools (Network tab), capture the POST request to /users or similar, noting the Cookie header and authenticity_token in the body.

**Expected Output**: Request details showing cookies like _stocky_session=... and authenticity_token=...
