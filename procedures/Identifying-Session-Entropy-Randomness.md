# Identifying Session Entropy/Randomness

## Summary

This procedure tests the randomness (entropy) of session identifiers in a web application using Burp Suite's Sequencer module. Low entropy in session IDs can allow attackers to guess or brute-force valid sessions, leading to session hijacking. By capturing and analyzing multiple session tokens, you can assess if the application's session management uses sufficiently random generation methods.

## Description

Session entropy refers to the unpredictability and randomness of session identifiers generated by a web application. High entropy ensures that session IDs are difficult to guess, protecting against attacks like session prediction or fixation. This procedure uses Burp Suite Professional's Sequencer to perform a statistical analysis on captured session tokens, evaluating aspects such as bit entropy, character set distribution, and overall randomness. It is particularly useful during web application penetration testing to identify weaknesses in session management, aligning with OWASP Top 10 categories like Broken Access Control and Identification and Authentication Failures. The test involves intercepting login requests, isolating the session token, capturing a sample of tokens through repeated logins, and analyzing the results for patterns or predictability.

## Requirements

1. Burp Suite Professional (Sequencer module requires the paid version).
2. Configured browser proxy to route traffic through Burp Suite.
3. Valid login credentials for the target web application.
4. Network access to the target web application.
5. At least 100-500 login attempts for a reliable sample size (depending on application rate limiting).

## Defense

- Implement cryptographically secure random number generators (e.g., CSPRNG) for session ID creation to ensure high entropy.
- Use session IDs with sufficient length (at least 128 bits) and a broad character set.
- Monitor for unusual login patterns or session ID predictability through logging and anomaly detection.
- Enforce HTTPS to prevent session ID interception and regenerate sessions on privilege changes.

## Objectives

1. Capture a statistically significant sample of session identifiers from the target application.
2. Analyze the entropy and randomness of the session tokens to identify potential weaknesses.
3. Determine if the session management is vulnerable to prediction or brute-force attacks.
4. Provide recommendations for improving session security if low entropy is detected.

## Instructions

### Step 1: Configure Proxy and Perform Initial Login

**Context**: Set up Burp Suite as a proxy to intercept traffic and perform a login to the target application. This establishes a baseline session and allows identification of the session token location.

Navigate to the login page of the target web application in your proxied browser. Enter valid credentials and submit the login form. In Burp Suite's Proxy > HTTP history tab, locate the intercepted login POST request.

### Step 2: Send Login Request to Sequencer

**Context**: Isolate the session token by sending the captured login request to the Sequencer for analysis preparation. This step defines the token extraction point.

Right-click the login request in the Proxy history and select "Send to Sequencer." In the Sequencer window, go to the "Token definition" section.

### Step 3: Define Token Location

**Context**: Specify the exact location of the session identifier within the request or response. This ensures Sequencer focuses on the relevant part for randomness testing.

In the Sequencer, select "Configure token" and choose the appropriate location (typically a cookie named like JSESSIONID or a custom session cookie). Highlight the session ID value in the request/response to define the token boundaries. Click "OK" to confirm.

### Step 4: Start Live Capture and Generate Tokens

**Context**: Collect a sample of session tokens by repeatedly logging in. This provides the data needed for statistical analysis.

Click "Start live capture" in the Sequencer. Return to the browser and perform multiple logins (aim for 100+ iterations, logging out each time if necessary to generate new sessions). Monitor the capture progress in Sequencer. Once sufficient tokens are captured, click "Stop live capture" followed by "Analyze now."

### Step 5: Review Analysis Results

**Context**: Interpret the Sequencer output to evaluate randomness. Look for overall entropy ratings and per-character analysis.

In the "Analysis" tab, review the results. Check the "Overall result" for a summary (e.g., "Good," "Acceptable," or "Weak"). Examine charts for bit entropy, popular values, and character distribution. If entropy is low (e.g., below 6.0 bits per character), the session IDs may be predictable.

> **Note**: Repeat captures if rate limiting occurs, and consider platform-specific factors like session storage (cookies vs. URL parameters).
