# Identify Correct Verification Code from Response Length

## Summary

This procedure analyzes Burp Intruder results to detect the successful verification by identifying the unique shorter response length for the correct 6-digit code.

## Description

Invalid code submissions to the Evernote endpoint return error messages, resulting in longer HTTP responses (e.g., 400+ bytes with JSON errors). Successful verification yields a concise success response (~373 bytes, likely a redirect or minimal JSON). By sorting Intruder results by response length, the outlier short response reveals the code. This passive analysis confirms brute-force success without additional requests.

## Requirements

1. Completed Intruder attack results
2. Burp Suite for result viewing
3. Basic understanding of HTTP response structures

## Defense

Defensive measures and detection strategies:

- Standardize response lengths/sizes for success and failure to obscure differences
- Avoid verbose error messages in responses
- Use behavioral analytics to detect bulk request patterns

## Objectives

1. Distinguish valid code response from failures
2. Extract the correct 6-digit code for use in setup
3. Validate brute-force efficacy without re-testing

## Instructions

### Step 1: Review Intruder Results

**Context**: Examine the table of responses generated by the attack.

Open the Intruder results tab post-attack.

> Sort columns by 'Length' ascending; scan for the shortest response (~373 bytes) amid longer ones.

### Step 2: Inspect the Short Response

**Context**: Confirm the response indicates success.

Click the short response to view details.

> Check for success indicators like 200 OK status, no error JSON, or redirect headers. Note the corresponding payload (the code).

### Step 3: Verify Manually if Ambiguous

**Context**: Optional re-test to confirm.

Copy the candidate code to Repeater.

> Submit in Burp Repeater; match the short response to validate.
