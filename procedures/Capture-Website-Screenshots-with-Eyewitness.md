# Capture-Website-Screenshots-with-Eyewitness

## Summary

This procedure uses the Eyewitness tool to capture screenshots of websites, either a single URL or a list of URLs from a file, leveraging a headless Selenium browser for automated visual reconnaissance. It is useful for quickly assessing the visual layout, technology stack indicators, or changes in web applications during penetration testing or red team engagements.

## Description

Eyewitness automates the process of visiting HTTP/HTTPS endpoints and taking high-resolution screenshots using headless Chrome via Selenium. This technique is commonly employed in the reconnaissance phase to gather visual intelligence on target web applications without manual browsing. It supports single targets for quick checks or batch processing from files generated by tools like httpx or subfinder, allowing pentesters to identify login pages, admin panels, or outdated software visually. The procedure requires Python and Selenium dependencies, and outputs screenshots organized by hostname in a directory structure for easy review. In a typical attack scenario, this follows subdomain enumeration to visualize the attack surface.

## Requirements

1. Eyewitness tool installed (see [[tools/eyewitness]] for installation).
2. Python 3 with Selenium and ChromeDriver.
3. Network access to target URLs (no authentication required for basic screenshots).
4. Optional: A text file containing a list of URLs (one per line) from prior reconnaissance tools like httpx.

## Defense

Defensive measures and detection strategies:

- Web Application Firewalls (WAFs) like Cloudflare or ModSecurity can detect and block automated browser traffic patterns from headless Chrome (e.g., via User-Agent analysis or JavaScript challenges).
- Server-side logging of unusual request volumes or Selenium-specific headers; monitor for rapid successive GET requests from the same IP.
- Implement rate limiting on web servers to throttle screenshot attempts.

## Objectives

1. Capture visual snapshots of target websites to identify potential entry points or misconfigurations.
2. Automate reconnaissance for multiple endpoints to save time in large-scale assessments.
3. Verify the presence and basic structure of web applications without interactive access.

## Instructions

### Step 1: Capture Screenshot of a Single URL

**Context**: This step uses Eyewitness to take a screenshot of one specific website, ideal for initial validation or spot-checking a high-value target. It launches a headless browser, visits the URL, and saves the screenshot with metadata.

**Command** ([[commands/eyewitness-screenshot-single-url]]):
```bash
eyewitness --web --single https://$_TARGET_URL
```

> This command starts Eyewitness in web mode (--web) and targets a single URL (--single). Replace $_TARGET_URL with the actual site (e.g., https://example.com). The tool will output a directory named after the hostname containing the screenshot (e.g., screenshots/example.com.png) and a JSON report with details like page title and load time. Success is indicated by the creation of the output directory without errors related to connectivity or browser launch.

### Step 2: Capture Screenshots from a List of URLs

**Context**: For broader reconnaissance, this optional step processes a file of URLs (e.g., from httpx output) to batch-screenshot multiple sites. It organizes outputs by hostname, filtering out non-responsive URLs, and is efficient for subdomain takeovers or application mapping.

**Command** ([[commands/eyewitness-screenshot-list-of-urls]]):
```bash
eyewitness --web -f $_URL_FILE
```

> Run this after preparing a file ($_URL_FILE, e.g., http.txt) with one URL per line. The --web flag enables headless mode, and -f specifies the input file. Eyewitness will visit each URL, capture screenshots for responsive ones, and generate a report.json summarizing results (e.g., successful captures, timeouts). If a URL fails (e.g., 404 or timeout), it notes it in the output; review the screenshots/ directory for visuals. This step expands on single-URL capture for scalability.
