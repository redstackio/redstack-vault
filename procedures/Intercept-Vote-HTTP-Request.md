# Intercept Vote HTTP Request

## Summary

This procedure captures the HTTP POST request generated by clicking a vote button on an Urban Dictionary definition page, allowing export to curl format for later parallel execution in the race condition exploit.

## Description

The voting system sends asynchronous AJAX requests to an endpoint like /vote/definition_id. Using browser dev tools or a proxy, the attacker intercepts this request, including headers (e.g., X-Requested-With: XMLHttpRequest, cookies for session), POST data (vote direction, definition ID), and response. This enables replication outside the browser to exploit concurrency. Prerequisites include access to the page from Step 1. Outcomes: A reusable curl command for vote submission.

## Requirements

1. Browser with dev tools or Burp Suite proxy
2. Network interception capability
3. Basic knowledge of HTTP requests

## Defense

Defensive measures and detection strategies:

- Enforce CSRF tokens in vote requests
- Log and alert on intercepted/modified requests via WAF

## Objectives

1. Capture exact vote request structure
2. Export for offline replay
3. Identify endpoint and parameters

## Instructions

### Step 1: Enable Interception

**Context**: Set up tools to monitor network traffic before interacting with the vote button.

For [[tools/Chrome-Developer-Tools]]:

```bash
# Open Dev Tools (F12), go to Network tab, clear logs, then click vote button
```

> Filter for XHR/Fetch requests. Right-click the vote POST and select "Copy as cURL".

For [[tools/Burp-Suite]]:

```bash
# Configure browser proxy to 127.0.0.1:8080, intercept request in Proxy tab
```

> Forward the request and export from Repeater as curl.

### Step 2: Trigger and Copy Request

**Context**: Submit a single vote to generate the interceptable request.

Click the up or down button on the page.

> Expected: Captured request like `curl -X POST -H "Cookie: ..." -d "vote=up&defid=123" https://www.urbandictionary.com/api/vote`.
