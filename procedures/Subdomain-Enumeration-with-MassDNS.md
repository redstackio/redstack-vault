# Subdomain-Enumeration-with-MassDNS

## Summary

This procedure uses MassDNS to perform high-speed DNS resolution on a list of potential subdomains, typically generated by tools like Subfinder, to identify valid subdomains associated with a target domain. It is particularly useful for resolving large wordlists efficiently when standard resolvers are rate-limited or slow.

## Description

Subdomain enumeration is a key reconnaissance technique to map out a target's attack surface by discovering hidden or forgotten subdomains that may host vulnerable services. MassDNS accelerates this by sending parallel DNS queries using a custom list of public resolvers, supporting A and AAAA record resolutions. This procedure assumes an input file of potential subdomains (e.g., from passive or brute-force enumeration) and outputs resolved ones with their IP addresses. It is effective in environments where DNS queries need to be evaded or scaled, such as during red team engagements targeting large domains. The target environment is any domain with public DNS resolution, requiring no special access beyond internet connectivity.

## Requirements

1. A list of potential subdomains in a text file (one per line), e.g., from Subfinder output.
2. A file containing a list of reliable DNS resolvers (e.g., public DNS servers like 8.8.8.8).
3. MassDNS tool installed on a Linux system with network access to the target's DNS.
4. Write permissions to output directories (e.g., /tmp).

## Defense

- Monitor for high-volume DNS queries from unusual sources using tools like DNS firewalls or SIEM rules.
- Implement DNSSEC to prevent resolution spoofing and rate-limit queries per IP.
- Regularly audit and secure unused subdomains to reduce the attack surface.
- Use services like certificate transparency logs to detect unauthorized subdomains early.

## Objectives

1. Resolve a large list of potential subdomains to identify valid ones.
2. Map the target's infrastructure by associating subdomains with IP addresses.
3. Uncover potential entry points or misconfigurations in the target's domain structure.

## Instructions

### Step 1: Prepare Input Files

**Context**: Ensure you have the subdomain list (e.g., results_subfinder.txt) and a resolvers file (e.g., resolvers.txt with one DNS server IP per line). This step sets up the inputs for efficient parallel resolution.

No command required for preparation; manually create or obtain these files. For resolvers, use public lists from trusted sources to avoid blacklisting.

> Verify files exist: Use `ls /tmp/results_subfinder.txt ./resolvers.txt` to confirm. Expected output: File paths listed without errors.

### Step 2: Resolve Subdomains with MassDNS

**Context**: Pipe the subdomain list into MassDNS for bulk resolution, specifying A records, sorted output, and writing results to a file. This step performs the core enumeration, leveraging multiple resolvers for speed and reliability.

**Command** ([[commands/massdns-resolve-subdomains-from-file]]):
```bash
DNS_RESOLVERS="./resolvers.txt"
cat /tmp/results_subfinder.txt | massdns -r $DNS_RESOLVERS -t A -o S -w /tmp/results_subfinder_resolved.txt
```

> This sets the resolver path in a variable, reads subdomains via cat, and runs MassDNS with flags for A records (-t A), sorted output (-o S), and output file (-w). Run in a directory with write access. Expected output: A file with lines like "subdomain.target.com. A 192.168.1.1" for resolved entries; unresolved ones may appear as NXDOMAIN.
