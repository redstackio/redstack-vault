# Capture-and-Analyze-SSRF-Request

## Summary

This procedure captures the incoming request generated by the SSRF trigger on the attacker's listener and analyzes it to confirm exploitation, extracting details like headers and origin for further assessment.

## Description

Following the SSRF trigger, the target server sends a request to the attacker's endpoint. This procedure uses the existing netcat listener to log the full request, including HTTP method, headers (e.g., User-Agent revealing server software), and any payload. In a DoD context, this could expose internal network details. Analysis helps validate the vuln and plan next steps like port scanning via SSRF.

## Requirements

1. Active listener from setup procedure
2. Network visibility to the target's outbound traffic
3. Basic knowledge of HTTP request format

## Defense

Defensive measures and detection strategies:

- Implement request logging on all outbound server connections
- Use IDS/IPS to flag connections to suspicious IPs/ports
- Disable unnecessary URL fragment processing in web apps

## Objectives

1. Receive and log the unauthorized request
2. Extract indicators of successful SSRF
3. Identify opportunities for escalation (e.g., internal access)

## Instructions

### Step 1: Monitor Listener Output

**Context**: With netcat running, wait for the SSRF-triggered connection and capture data.

**Command** ([[commands/nc-listen]]):
```bash
nc -lvp 8080
```

> Upon trigger, output shows: e.g., "Connection from target-ip 12345 received! GET / HTTP/1.1 ...". Copy the full request for analysis.

### Step 2: Analyze Captured Data

**Context**: Parse the logged request to confirm SSRF and gather intel.

No specific command; manually review output for:
- Origin IP (target server)
- Headers (e.g., Host, User-Agent)
- Request path (matches fragment)

> Success if request originates from target domain, not browser.
