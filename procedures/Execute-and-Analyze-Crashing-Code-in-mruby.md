# Execute and Analyze Crashing Code in mruby

## Summary

This procedure executes invalid Ruby code in mruby to trigger segmentation faults, analyzes the generated bytecode for invalid jumps, and tests variations to confirm the bug's behavior.

## Description

Running the crafted code causes the mruby interpreter to generate bytecode with invalid OP_JMP instructions, leading to crashes or execution beyond program boundaries. Variations help isolate the issue to constants and ||=.

## Requirements

1. mruby interpreter (commit 0ff3ae1fbaed62010c54c43235e29cdc85da2f78)
2. Sandbox environment for alternative execution
3. Access to run Ruby scripts

## Defense

Defensive measures and detection strategies:

- Restrict execution of untrusted Ruby code
- Monitor for segfaults in embedded Ruby VMs

## Objectives

1. Reproduce crash
2. Analyze bytecode anomalies
3. Confirm bug specifics through variations

## Instructions

### Step 1: Run Crashing Code

**Context**: Execute the invalid code to cause segfault.

**Command** ([[commands/mruby-crash]]):
```bash
mruby crash.rb
```

> Expected: Segmentation fault due to invalid jump.

### Step 2: Run in Sandbox

**Context**: Alternative execution to crash including parent MRI VM.

**Command** ([[commands/sandbox-crash]]):
```bash
sandbox crash.rb
```

> Expected: Segmentation fault.

### Step 3: Test Non-Crashing Variations

**Context**: Compare with non-crashing code to isolate bug.

**Command** ([[commands/mruby-non-crash]]):
```bash
mruby non-crash.rb
```

> Uses lowercase variable; no crash.

**Command** ([[commands/mruby-larger]]):
```bash
mruby larger.rb
```

> Multiple breaks for larger invalid jumps.

**Command** ([[commands/mruby-non-crash]]):
```bash
mruby non-crash-other.rb
```

> Uses &&=; no crash.

### Step 4: Analyze Bytecode

**Context**: Examine AST and bytecode for invalid OP_JMP.

Use mruby tools to inspect generated bytecode showing jumps beyond sequence.
