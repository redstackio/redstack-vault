# generate-and-use-imdsv2-token

## Code

```bash
export TOKEN=`curl -X PUT -H "X-aws-ec2-metadata-token-ttl-seconds: 21600" "http://169.254.169.254/latest/api/token"`
curl -H "X-aws-ec2-metadata-token:$TOKEN" -v "http://169.254.169.254/latest/meta-data"
```

## Description

This bash script generates a session token for AWS IMDSv2 and uses it to query instance metadata securely. It demonstrates the token-based authentication required after enabling IMDSv2, preventing SSRF exploitation by ensuring requests are authorized.

## Parameters

| Variable | Description | Example |
|----------|-------------|---------|
| TOKEN | Environment variable holding the generated session token (TTL: 21600 seconds / 6 hours) | (auto-generated by curl) |
| X-aws-ec2-metadata-token-ttl-seconds | Header specifying token lifetime in seconds | 21600 |

## Usage

Run this script from within an EC2 instance with IMDSv2 enabled. It first requests a token via PUT to the token endpoint, stores it in the TOKEN variable, then uses it in a GET request to fetch metadata. Integrate this pattern into applications needing metadata access, such as scripts retrieving IAM roles. Start with a netcat listener or logger if testing network behavior.

## Detection

- Monitor for unusual PUT requests to 169.254.169.254/latest/api/token via VPC Flow Logs or CloudTrail.
- Look for 401 errors on metadata endpoints indicating failed token attempts, signaling potential SSRF probes.
- Enable instance logging to track curl or similar tool usage targeting the metadata IP.
