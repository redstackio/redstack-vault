# SQLite-Randomized-String-Matching-Delay-Payload

## Code

```sql
AND [RANDNUM]=LIKE('ABCDEFG',UPPER(HEX(RANDOMBLOB([SLEEPTIME]00000000/2))))
```

## Description

This SQL code snippet is a payload for time-based blind injection in SQLite databases. It uses a conditional equality check with LIKE operator on a fixed string 'ABCDEFG' against the hexadecimal representation of a random blob generated by RANDOMBLOB. The blob size, controlled by [SLEEPTIME], causes a delay proportional to its size due to computation overhead, as SQLite lacks a native sleep function. The randomization via RANDNUM and blob helps in obfuscating the payload to bypass basic filters while enabling boolean-based inference.

## Parameters

| Variable | Description | Example |
|----------|-------------|---------|
| [RANDNUM] | Random numeric value for the left side of the equality (e.g., 1 for always-true condition) | 1 |
| [SLEEPTIME] | Approximate delay in milliseconds, converted to blob size (e.g., 5000 for ~5s delay; adjust based on server) | 5000 |

## Usage

Inject this payload into a vulnerable parameter in a web app query, e.g., ' AND [code] --. Use in conditional contexts like CASE WHEN (data='A') THEN [code] ELSE 1 END to delay only if true. Automate with scripts measuring response times > threshold to extract data char-by-char. Commonly used in Burp Intruder or sqlmap for blind SQLite SQLi.

## Detection

- WAF rules flagging SQL functions like RANDOMBLOB, HEX, UPPER in inputs.
- Server logs showing long-running queries or high CPU from blob generation.
- Response time monitoring: Anomalous delays (>2x normal) on specific endpoints.
- Network traffic analysis for repeated similar requests with timing variations.
